# 1C Session Control

Приложение на FastAPI обнаруживает кластеры, информационные базы и активные сеансы через штатный `rac.exe`. Веб-интерфейс читает готовый фоновый снимок и обновляется каждые две секунды без перезагрузки страницы. Для каждой компании можно задать общий лимит и включить выборочное завершение лишних интерактивных пользовательских сеансов. Администраторы, явно исключённые пользователи, фоновые задания, сервисы и конфигуратор не учитываются и не завершаются.

## Требования

- Windows Server и Python 3.14 x64;
- установленный сервер администрирования 1С (RAS);
- `rac.exe` той же версии платформы, что и администрируемый кластер;
- права администратора кластера, если кластер требует аутентификацию.

## Запуск

1. Установите зависимости:

   ```powershell
   py -3.14 -m pip install -r requirements.txt
   ```

2. Скопируйте `config.example.toml` в `config.toml` и укажите реальный путь к `rac.exe` и RAS-серверы.
3. Если нужны учётные данные, задайте переменные среды, указанные в конфигурации:

   ```powershell
   $env:SESSION_CONTROL_CLUSTER_USER = 'admin'
   $env:SESSION_CONTROL_CLUSTER_PASSWORD = 'secret'
   ```

4. Запустите FastAPI:

   ```powershell
   py -3.14 -m uvicorn app:api --host 0.0.0.0 --port 8000
   ```

   Интерфейс: `http://server:8000/`, JSON API: `/api/snapshots`, проверка приложения: `/health`, OpenAPI: `/docs`.

   При открытии интерфейс запрашивает логин и пароль администратора кластера 1С. Пароль хранится только в памяти процесса и удаляется при выходе или перезапуске приложения. После входа администратор может создавать компании, назначать им обнаруженные информационные базы и просматривать общие активные сеансы по базам каждой компании. Компании и привязки сохраняются в `data/session-control.db`.

   Для другого пути конфигурации задайте `SESSION_CONTROL_CONFIG`.

5. Проверьте доступность в консольном режиме:

   ```powershell
   py -3.14 app.py --check
   ```

6. Получите базы и активные сеансы в консольном режиме:

   ```powershell
   py -3.14 app.py
   ```

Ошибки `rac.exe` пишутся в stderr и в UTF-8 журнал `logs/session-control.log`; пароль в журнал не попадает. Недоступность одного RAS-сервера не мешает опросу остальных. Код возврата `0` означает, что доступен хотя бы один настроенный сервер, `1` — недоступны все серверы, `2` — ошибка конфигурации, `3` — не запускается `rac.exe`.

## Проверка парсера

```powershell
py -3.14 -m unittest discover -s tests -v
```

Команды RAC сосредоточены в `onec/rac.py`. Перед эксплуатацией следует сверить их с `rac help`, `rac cluster --help`, `rac infobase --help` и `rac session --help` именно установленной версии платформы.
